La grande confusion
!

print parle à l'humain.
return parle au programme.

Une fonction qui print est un cul-de-sac.

Notes Le faire vivre par l'échec : def double(n): print(n*2), puis resultat = double(5), puis resultat + 1 → TypeError. Trente secondes, effet garanti.
Anatomie d'une fonction
def saluer(prenom: str) -> str:
    """Rend un message de salutation."""
    return f"Bonjour {prenom} !"

message = saluer("Awa")

La docstring documente. Essaie help(saluer) : elle s'affiche.

Règle professionnelle
!

Jamais d'except nu.

On nomme l'erreur qu'on attend : except ValueError:

Notes Un except nu masque aussi le Ctrl+C et les vrais bugs. C'est une règle de métier, pas une préférence de style.
match / case — Python 3.10+
match choix:
    case "1": ajouter()
    case "2": afficher()
    case "3": quitter()
    case _:   print("Choix invalide")

Plus lisible qu'une cascade de elif quand on compare une variable à des valeurs fixes.
