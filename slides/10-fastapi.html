Notes Conséquence directe : tu n'écris plus jamais de if not isinstance(...). Et le message d'erreur indique précisément quel champ pose problème.
Un modèle
class Opportunite(BaseModel):
    titre: str = Field(min_length=3, max_length=200)
    pays: str
    deadline: date

    @field_validator("pays")
    @classmethod
    def normaliser(cls, v): return v.strip().title()

La validation s'exécute avant le code métier. Le nettoyage de la séance 7 devient inutile pour tout ce qui passe par l'API.

Attention aux tutoriels
!

FastAPI ne supporte
plus Pydantic v1.

Tout contenu antérieur à 2024 est périmé.

v1 → v2 : la table à connaître

À gauche, ce qui n'existe plus.

@validator→ @field_validator
.dict()→ .model_dump()
parse_obj()→ model_validate()
class Config→ model_config = ConfigDict()
Entrée et sortie

Deux modèles, jamais un seul.

✗

OpportuniteCreation

ce que le client envoie

Pas d'identifiant : le serveur l'attribue.

✓

OpportuniteLecture

ce que le serveur rend

Identifiant + champs calculés.

Notes Confondre les deux, c'est laisser un client imposer un identifiant ou lire un champ interne.
